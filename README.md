# ARAKETTIK — статический каталог

Существующий сайт работает на GitHub Pages без сервера, платного ИИ и автоматического сбора. Telegram-бот в папке `bot` отложен и не подключён.

## Добавить мероприятие без написания кода

1. Откройте `editor.html` в папке сайта или по адресу вашего сайта `/editor.html`. Редактор сохранён для владельца; ссылка на него не показывается в публичных контактах.
2. Вставь объявление. Подписанные поля «Название:», «Организатор:», «Город:», «Дедлайн:», «Ссылка:» заполняются автоматически. Обычный текст также принимается, но остальные поля нужно проверить.
3. Выбери раздел, категорию, город/страну, точный дедлайн и часовой пояс. Заполни подробности для «Подробнее». Прикрепи исходное изображение — редактор его не изменяет.
4. Нажми «Сохранить и показать карточку». Это локальная подготовка: посетители сайта её ещё не видят.
5. Скачай `manual-content.js`. На GitHub в существующем репозитории замени одноимённый файл: Add file → Upload files → выбери файл → Commit changes. После обновления GitHub Pages карточка появится у всех.

Если в карточках есть фотографии, лучше выбрать **«Скачать пакет с изображениями»**. Распакуй ZIP и загрузи `manual-content.js` вместе с папкой `assets` в корень того же репозитория. Изображения сохраняются отдельными файлами, без изменения исходных байтов; это уменьшает файл данных и позволяет загружать фотографии по мере просмотра. Обычный экспорт одним JS-файлом также работает, но встраивает изображения внутрь.

Повторное обновление: открой редактор и выбери «Изменить» у карточки. Экспорт содержит все его записи, а не только последнюю. Для переноса на другое устройство используй резервную копию JSON. Не заменяй файл сайта пустым экспортом: это удалит ранее добавленные вручную карточки.

Редактор — инструмент подготовки владельца, а не публичная форма отправки заявок. Он не имеет серверных прав. Открытие редактора другим посетителем не меняет опубликованный сайт. Черновики хранятся в браузере и могут исчезнуть при очистке его данных; резервная копия нужна для сохранности.

## Дедлайны

Проверка от 14 октября 2026: из 71 международной и 4 местных записей в публичной версии оставлены 64 международных и один подтверждённый местный конкурс. Закрытые наборы без нового объявления, записи с противоречащими календарями и неподтверждённым путём участия вынесены в `qa/eligibility-audit-2026-10-14.json`; объяснения и официальные источники — в одноимённом Markdown-отчёте. Для каждого опубликованного международного предложения сохранены `kyrgyzstanEligibility` и ссылка на условия. Возраст, место проживания, учебный статус, рабочее разрешение и ограничения отдельных вакансий учитываются отдельно от гражданства.

Даты и статусы хранятся в файлах данных, без повторных исправлений поверх них в интерфейсе. Для JJ/WBGSP записаны два окна конкурса: при паузе между ними отображается следующий набор, после последнего срока карточка исчезает. Подтверждённый будущий набор не обозначается открытым до начала подачи. Наборы с непубликованным точным днём открытия не открываются по выдуманной дате.

Карточки обоих каталогов скрываются при достижении `deadlineAt`. В открытой вкладке проверка выполняется каждые 30 секунд и при возвращении на сайт. Дата и время учитывают записанное смещение UTC.

По решению владельца дополнительно убраны сроки до **15 октября 2026 включительно** (`removedThrough` в `site-config.js`). Исторические записи с неоднозначным сроком не выдаются за актуальный набор. Удалённые/неподтверждённые местные объявления перечислены в `qa/removed-local-events.txt`.

Местный срок без времени в прежней базе обрабатывается как конец дня в Бишкеке. Международная дата без подтверждённого часового пояса скрывается после завершения дня во всех часовых поясах, чтобы не закрыть возможность раньше срока; точное время всё равно нужно проверить у организатора. Для новых записей редактор требует время и часовой пояс. Неизвестный дедлайн не угадывается.

## Файлы

- `catalog-data.js` — текущие местные записи.
- `event-card-view.js` — согласованный формат Б для Кыргызстана: короткое описание, место, аудитория, известная стоимость и отдельный дедлайн. Его используют сайт и предпросмотр редактора. Если фотография есть, она показывается целиком; если её нет, карточка использует компактную верхнюю плашку.
- `opportunities-data.js`, `new-opportunities.js`, `extra-opportunities.js`, `opportunities-details.js`, `opportunities-images.js` — единственный международный каталог и описания.
- `manual-content.js` — записи, добавленные владельцем через редактор.
- `knowledge-content.js` — расширенные статьи.
- `organization-updates.js` — уточнения организаций, логотипы, Interact и Nomad Volunteers.
- `assets/current-sources.json` — происхождение новых изображений.

Не создавай вторую международную секцию в `index.html`: текущая версия находится в `opportunities.html`. Категории остаются фильтрами. Основная навигация содержит пять разделов, выбор региона сохранён, на телефоне — две карточки в ряд.

Для некоторых организаций официальный знак не найден или идентичность не подтверждена. Вместо выдуманной эмблемы показываются инициалы. Список таких записей: `qa/organization-logos-pending.json`. Логотипы региональных филиалов Красного Полумесяца представляют национальную сеть, а не отдельный знак каждого филиала.

## Проверка

```powershell
node qa/verify-static-catalog.cjs
node qa/verify-eligibility-audit.cjs
```

Сценарий проверяет пять пунктов меню, отсутствие старого каталога и запросов к серверным API, дедлайны, фильтры, подробности всех международных карточек, статьи, логотипы и редактор с экспортом. Браузер: установленный Edge; Playwright берётся из локального runtime Codex.

При обновлении GitHub Pages загружай все изменённые файлы и новые изображения. Добавлены версии `?v=20261014` к JS/CSS, чтобы браузер не показывал прежний интерфейс из кэша.
